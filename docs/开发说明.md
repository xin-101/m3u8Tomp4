# m3u8ToMp4 开发说明

## 架构总览

- UI 层：`app/ui/`（main_window、task_widget、history_page、settings、parse_dialog）
- 核心层：`app/core/`（m3u8_parser、downloader、task_manager、ffmpeg_engine、speed_controller）
- 数据层：`app/database/sqlite.py`（download_task + history 两张表, WAL 模式, 线程安全）
- 浏览器层：`app/browser/extension_api.py`（本地 HTTP API, 127.0.0.1:18888）
- 插件：`browser-extension/`（Chrome Extension MV3）

## 关键设计

### 下载流程

TaskWorker(QThread) per task：
1. 解析 m3u8(`m3u8_parser.parse_m3u8`)→ 生成 `TaskState` 并持久化到 `download_cache/<id>/state.json`
2. 检查已存在的已完成分片 → `ThreadPoolExecutor` 并发下载剩余分片
3. 每个分片经 `SpeedController`(令牌桶) 限速, AES-128 密钥即时解密
4. 全量完成后 → `FFmpegEngine.convert_blocking`(`-c copy` 失败自动回退 libx264/aac) → 输出到下载目录

### 断点续传

- `TaskState` / `SegmentRecord` 记录每个分片的 `done/size/duration`
- 暂停=设标志位+退出 worker(线程结束, 释放并发槽)，状态已落盘
- 恢复=重新 launch worker, 读取 state.json, 跳过已完成分片
- 关闭程序时 `TaskManager.stop_all` 取消当前任务，`_run_inner` 检测暂停/取消分支把最新状态写盘

### 状态机

TaskInfo.status ∈ 等待 / 解析中 / 下载中 / 暂停 / 合并中 / 转换中 / 完成 / 失败
TaskManager 用 `_pending` 队列 + `_active` 字典管理任务，`_pump()` 按 max_concurrent 自动拉起。

### FFmpeg 引擎

- `locate_ffmpeg()` 依次查：设置指定路径 → resources/(frozen & 源码) → 系统 PATH
- `convert_blocking()` 基于 `QProcess` 阻塞 API 泵送 `-progress pipe:1` 输出, 不依赖 Qt 事件循环(QThread/普通线程均可)
- 失败自动回退：首遍 `-c copy`（含 `-fflags +genpts`, MP4 加 `+faststart`），失败重试 `libx264 -preset fast -crf 20 + aac 192k`

### UI/子线程隔离

- 下载/转换均在 QThread 中运行, UI 不阻塞
- 信号链：`TaskManager.task_* → MainWindow → TaskPage.update_task`
- 进度上报用纯 Python 线程(0.5s 一次)，避免 QTimer 无事件循环环境失效

## 目录说明

- `resources/ffmpeg.exe`：便携版 FFmpeg(7.1), 打包时随 `--add-data resources;resources` 嵌入
- `download_cache/<task_id>/`：分片文件 + `state.json` + `key.bin` + 本地 `local.m3u8`
- `logs/`：`app.log`（RotatingFileHandler，2MB×3）+ `m3u8ToMp4.db`
- `docs/`：用户手册/开发说明/测试报告
- `browser-extension/`：可加载的 Chrome MV3 扩展
